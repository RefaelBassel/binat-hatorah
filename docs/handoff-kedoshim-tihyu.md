## חלק א — לעשות עכשיו

### א.1 ⚠️ "ביטול פרסום" מוחק את עבודת התלמידים — לתקן לפני שימוש בכיתה

**המצב היום** — `app/dashboard/task/[taskId]/actions.ts`, הפונקציה `unpublishTask`:
מוחקת לצמיתות את שורת המשימה **וכל מה שקשור אליה**: `task_assignments`,
`task_progress`, `task_answers`, `text_markings`, `grades`, `assist_log`, `reflections`
(ומאפסת `question_bank.task_id`). אין דרך חזרה. אם המורה תלחץ עליו כדי "להוריד
זמנית" משימה שכיתה כבר עבדה עליה — כל התשובות והציונים יימחקו.

**ההתנהגות הנדרשת** (כפי שקיימת בבינת התורה, `lib/tasks.ts` — `cancelTaskAssignment`,
`republishTask`, `isTaskCancelled`):

1. **ביטול** = מסירים את המשימה מכל התלמידים (`DELETE FROM task_assignments WHERE task_id = ?`)
   ו**משאירים את כל השאר במקום**: progress, answers, markings, grades, reflections.
   מסמנים את המשימה בטבלת סימון `task_cancellations (task_id PK, cancelled_at)`.
2. **פרסום מחדש** = מוחקים את הסימון ומקצים שוב לכל תלמיד/ה שסיים/ה onboarding
   (`INSERT OR IGNORE INTO task_assignments`). העבודה הישנה חוזרת להופיע כאילו לא קרה כלום.
3. **הצטרפות מאוחרת** — ההקצאה האוטומטית ב-onboarding חייבת **לדלג** על משימות
   מסומנות כמבוטלות (אחרת תלמיד חדש יקבל משימה שהמורה ביטלה).
4. בדשבורד המורה: משימה מבוטלת מופיעה עם תג "בוטלה" וכפתור "פרסום מחדש";
   כפתור הביטול מבקש אישור (`ConfirmButton` — אין כאן קומפוננטה כזו; יש
   `window.confirm` ב-`task-admin.tsx`, זה מספיק). הנוסח בבינת התורה:
   "לבטל את ההקצאה של ״{כותרת}״? המשימה תוסר מכל התלמידים. העבודה שכבר נשמרה לא תימחק
   ואפשר יהיה לפרסם מחדש."
5. את `unpublishTask` ההרסני אפשר **להשאיר** רק כמחיקה מפורשת של משימה שאף אחד לא נגע בה
   (למשל: מותר רק כשאין שורות ב-`task_progress`), או להסיר לגמרי. להציע לרפאל ולשאול.

**הבדל קריטי מבינת התורה:** שם הטבלה נוצרת עצל בקוד (`CREATE TABLE IF NOT EXISTS`
בזמן ריצה). **באתר הזה אין יצירה עצלה** — הסכמה עוברת רק דרך migrations.
לכן: ליצור `migrations/0005_task_cancellations.sql`:

```sql
-- Marker table: a cancelled task is unassigned from everyone but all saved
-- work is kept, so the teacher can republish without losing anything.
CREATE TABLE IF NOT EXISTS task_cancellations (
  task_id      INTEGER PRIMARY KEY REFERENCES tasks(id),
  cancelled_at INTEGER NOT NULL
);
```

ואחרי המיזוג **להזכיר לרפאל להריץ** `node scripts/migrate.mjs` גם מול Turso של הייצור,
אחרת הכפתור יקרוס באוויר.

### התאמות שיידרשו דווקא כאן (כיתה ט) — ממתינות לתשובות של ריעות

הצ'אט של קדושים תהיו **חייב** לקבל תשובות לארבע השאלות האלה מרפאל לפני שמתחיל.
רפאל שואל את ריעות; עד אז אין מה לבנות.

**1. איפה יושב הצ'ק כשאין חלק א׳?**
בבינת התורה הצ'ק יושב בין הפענוח (חלק א) לכתיבה (חלק ב). כאן כל משימות ויקרא ט״ז הן
`mode: "simple"` — **אין חלק א**; הקריאה נעשית בכיתה עם תנ"ך פיזי והאתר הוא דף עבודה
בלבד (`SIMPLE_STAGES = []`, השלב קופץ 1→8). שתי אפשרויות סבירות:
- הצ'ק **פותח** את דף העבודה: "קראנו יחד — עכשיו כמה שאלות מהירות" → דופק מיידי למורה
  עוד לפני שהתחילו לעבוד. (הנטייה שלנו — מנצל את זה שהקריאה הרגע קרתה בכיתה.)
- הצ'ק **סוגר** את דף העבודה.
במשימות `mode: "full"` (אם ייווצרו) — כמו בבינת התורה, בין חלק א לחלק ב.
כל קוד חייב לבדוק `stagesFor(content).length` ולא להניח 7 שלבים
(כמו ש-`class-status/route.ts` כבר עושה).

**2. אילו סוגי שאלות נכנסים לצ'ק?**
כאן יש מיומנויות שאין בבינת התורה ומתאימות מאוד לשאלות סגורות:
- **טעמי המקרא** — "איפה האתנחתא בפסוק ד׳?" / "איפה נגמר המשפט?" (רק אתנחתא=פסיק,
  סוף פסוק=נקודה — לא לשיים טעמים אחרים, לפי כללי האתר).
- **התמצאות בתנ"ך** — "באיזה ספר/חומש הפרק?" (בלי לתת מספרי פרק ופסוק בעזרה).
- **מילה קשה / הבנת הפשט** — כמו בבינת התורה.
אין כאן חלק טיעוני (`argument` מוגדר בטיפוסים ולא בשימוש), אז השאלות הן על קריאה,
טעמים והתמצאות. **התוכן של השאלות מגיע מריעות** — לא להמציא.

**3. מה בדיוק לדווח בהתראות הריכוז?**
זה חלק א.2 — אבל לוודא עם ריעות שהיא רוצה את אותם שלושה נתונים (יציאות, זמן בחוץ,
הדבקות שנחסמו) ואת אותו כלל "רקע לשיקול דעת, בלי השפעה על הציון".

**4. לפי כיתה, לא לפי שכבה.**
באתר הזה יש שדה **כיתה** (ט1/ט2…) ב-onboarding. דופק ההבנה, "היכן הכיתה מתקשה" ומסך
הסגירה חייבים להיות **מסוננים לכיתה שעכשיו בשיעור** — אחרת ט2 יצבע את הלוח של ט1.
לבדוק קודם אם דופק הכיתה הקיים (`class-pulse-drawer.tsx`, `class-board.tsx`,
`class-status/route.ts`) כבר מסנן לפי כיתה; אם לא — זו התאמה נדרשת גם לפיצ'ר הקיים.
לשאול את ריעות איך היא רוצה לבחור כיתה (בורר בדופק? לפי המשימה?).

**הבדלים נוספים לזכור:**
- מימדי הרפלקציה כאן שונים: `pshat_progress` = הבנת הפשט,
  `argument_progress` = קריאה, טעמי המקרא והתמצאות (ראה `migrations/0003_reflections.sql`).
  מד-ההבנה החדש **אינו** רפלקציה ולא נכנס לאותה טבלה.
- הטקסט המקראי כאן ב-David Libre (`.font-mikra`) עם טעמים — כל הצגת פסוק בצ'ק/במסך
  הסגירה/באור פותח משתמשת בו ומכבדת את מתגי הטעמים.
- הפנייה לתלמיד: `addressInstruction(user.addressForm)` (נקבה/זכר/ניטרלי) — חובה בכל
  פרומפט חדש, כולל עזר-החזרה למורה אם הוא מזכיר תלמידים בשמם.

## חלק ג — כללים שחלים על כל שינוי כאן

   חדשה להגיד לרפאל במפורש: "להריץ `node scripts/migrate.mjs` מול הייצור."
2. **עברית בממשק, אנגלית בקוד ובקומיטים.** אף מילה עברית ב-`className`/`id`/`data-*`.
3. **אין תוכן ספקולטיבי.** שאלות צ'ק, שאלות מליאה, תוכן שקפים — רק מריעות דרך רפאל.
4. **לפני קוד: תוכנית, הצעות התאמה משלך, ואישור.** אם יש שתי דרכים סבירות — לשאול.
5. **לא לשבור את ה-print pipeline.** כל שינוי בתוכן המשימות דורש `npm run build:print`
   וקומיט של הקבצים ב-`public/print/`.
